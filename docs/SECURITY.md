# Deployment and input security

The reference Compose setup is for local development. Set `MINSEARCH_DEPLOYMENT_MODE=production`, supply distinct random database/Redis passwords (at least 16 UTF-8 bytes), and supply an external HS256 signing secret (at least 32 bytes) for every application. The production guard refuses the bundled development values. Terminate HTTPS at a trusted ingress and restrict PostgreSQL/Kafka access to the private service network. Forwarded headers are ignored; rate limits use the direct peer address. Configure trusted proxy handling explicitly before relying on client IP limits behind an ingress.

Access tokens require the `minsearch` issuer, UUID subject and token ID, USER/ADMIN role, issuance and expiry, and HS256 signature. To rotate keys, deploy the new current secret with the retiring key in `MINSEARCH_SECURITY_JWT_PREVIOUS_SECRET` on all services, wait for the 15-minute access-token lifetime plus clock skew, then remove the previous key. New tokens always use the current key. Refreshes serialize by token family and row in PostgreSQL; reuse commits family revocation even though the HTTP request is rejected. Passwords are bounded to BCrypt's 72 UTF-8 bytes.

Browser access uses exact HTTP(S) origins from `MINSEARCH_SECURITY_CORS_ALLOWED_ORIGINS`; an empty allowlist disables cross-origin browser access. Security headers include CSP, frame protection, and content-type protection. Only authentication registration/login/refresh and health probes are public. Actuator metrics and admin analytics require ADMIN. API documentation requires authentication unless explicitly enabled for public development access.

API requests have bounded per-peer and per-subject minute buckets, with bounded bucket storage. Authentication also has a tighter 10-attempt/minute peer limit. Configure `minsearch.security.requests-per-minute` (default 1200, maximum 1000000) and `minsearch.security.max-json-bytes` (default 65536, maximum 1048576). Oversized JSON, including chunked bodies, returns 413. Rate rejection returns 429 and Retry-After. These process-local limits should be complemented by ingress limits when deploying multiple replicas.

Uploads accept TXT, Markdown, and PDF up to 10 MiB. Extensions, declared media types, and initial content bytes must agree. Filenames are sanitized display metadata; stored keys contain only server-generated UUIDs. SHA-256 is streamed. Text extraction rejects invalid UTF-8 and embedded NULs. Extraction is bounded by input size, 5 million characters, 1000 PDF pages, 100000 tokens, and 256 characters per indexed term. Configure these through `minsearch.extraction.*`.

PDF parsing runs in a disposable JVM, with at most two children, 128 MiB heap per child, a 10-second wall-clock limit, bounded text output, and a 100000-object limit. Encrypted PDFs are rejected. JVM settings `minsearch.pdf.worker-heap-mib`, `minsearch.pdf.timeout-seconds`, and `minsearch.pdf.max-objects` override these budgets. Heap/time isolation also bounds failures that occur while loading objects before the object count can be checked. Worker stdout/stderr are discarded; only stable failure descriptions reach document status. The packaged search image must include a Java runtime; the end-to-end suite exercises this launch path.

Queries default to 2048 characters, 100 lexical tokens, nesting depth 10, 100 prefix expansions, 50 fuzzy expansions, and edit distance 2. `minsearch.query.*` exposes validated bounds. Suggestions and autocomplete prefixes are bounded to 256 characters. Popular-query storage is bounded and expires. Invalid filters and malformed expressions return positioned errors.

Successful deletion records an audit event in the same database transaction. Authenticated ADMIN API attempts record actor, method, outcome, time, resource where available, and correlation ID in service-specific security audit tables. Audit records exclude credentials, raw queries, filenames, and document content. Restrict audit-table reads and apply a retention policy appropriate to the deployment. Unexpected API logs contain exception class and safe request metadata rather than exception messages or bodies.
